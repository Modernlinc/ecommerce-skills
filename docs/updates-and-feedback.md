# 更新与反馈

[首页](../README.md) · [使用指南](getting-started.md) · [获取帮助](../SUPPORT.md)

## 先围绕一个任务评估

从[十八项目录](skill-catalog.md)选一项，读取其独立输入和应交成果，用单文件试阅完成一个合成任务，再与编辑参考输出比较。没有真实业务资料时可以直接使用题设；公开评估无需提供账户权限或客户信息。

判断是否适合时，重点看材料要求、完整成果、未知项和下一步交接。参考输出展示成果形态，不保证任意模型、客户端或复杂任务都得到相同结果。

## 怎样提出反馈

- **产品适配**：说明想完成的任务、能提供的材料类型和准备使用的工具，不必先确定Skill名称。
- **资料问题**：给出公开版本、文件链接、最少复现步骤和预期/实际差别。
- **新场景建议**：说明现有哪项任务接不上、希望交什么成果；建议不等于新增能力已经承诺或实现。

在[仓库Issues](https://github.com/Modernlinc/ecommerce-skills/issues)提交非敏感问题。[SUPPORT](../SUPPORT.md)提供可直接复制的格式。不要在Issue里上传完整付费包、客户资料、账号、合同、付款或私人联系方式；敏感问题按[安全指引](../SECURITY.md)处理。

## 反馈怎样进入更新

维护时先确认资料版本和复现依据，区分缺文件/链接、题设或参考错误、环境差异、未覆盖能力。修复公共资料时同步调整相关输入、输出、说明或链接，完成仓库检查，并在[CHANGELOG](../CHANGELOG.md)记录实际改动。需要新证据的兼容性或业务能力保持待核，不因收到建议就宣布支持。

## 两套版本分别看

公开资料版本只标记本仓库的介绍、题设、参考和说明。完整产品的版本、支持环境、依赖与改动说明随独立交付确认；更新本仓库不会自动更新已安装的商业包。需要切换完整包时，应核对具体版本、文件清单和必要验证，保留原件后再切换。

仓库按实际资料变更维护，不承诺固定更新频率、未约定的支持时效或终身免费升级。完整产品的价格、许可、更新和售后条件见[交付前确认清单](evaluation-and-delivery.md)，以事前明确约定为准。
