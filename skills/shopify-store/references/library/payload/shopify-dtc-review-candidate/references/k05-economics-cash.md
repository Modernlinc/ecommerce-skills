# 经营与现金：明确范围内的候选计算

> 当前阅读入口：[当前状态与来源导航](../当前状态与来源导航.md)。本页旧日期/待验文字保留历史时点；涉及平台事实时先读取该导航列出的对应current_version_evidence及限制。

method_hypothesis，候选实现范围已获内部方法方案审阅；并非正式公司采用、独立终验或财税标准。输入约定和以下算法是公司原创设计；[官方利润报告](https://help.shopify.com/en/manual/reports-and-analytics/shopify-reports/report-types/default-reports/profit-reports)只提供报告范围与销售时成本覆盖背景，不为现金算法背书。发布日期unknown，formal_adoption=no。

## 1. 固定范围与字段

经营E记录店铺、市场、币种、时区、期间起止（含起不含止）、快照、报告名/版本、对象分母及采用事件发生期或订单cohort。默认仅采用输入明示的事件发生期，跨期退款仍需关联原sale，不悄悄换期。现金C另列支付通道、币种/期间、期初期末余额与结算/银行范围；两个期间不能混加。不同币种分别报告，不猜汇率。

保留每行source_row、store/source_system/type/event_id、事件与记录时间、状态、币种、raw_amount、amount_semantics、订单/行/ref_event、settlement_batch、coverage_group和依据。单位成本计算还需数量/单位。raw不覆盖，另建规范化列；未给语义则隔离并说明受影响结果。

## 2. 经营规范化、去重和覆盖

sale是材料声明已发生的商品收入，正值；写明是否净折扣/税/客户运费。已净折扣不得再扣折扣。refund必须有发生状态和原sale归属：已发生收入冲减为负值；request/pending只列待审，不进已发生总额。原始正数若明确“退款绝对额”才转负，不见符号猜性质。

商品成本/费用统一为支出正、返还或冲回负。fee_charge原始−4若定义为支出记+4；fee_return原始+1且明示返还则记−1。退款不自动冲成本，退回物/库存变动也不代替成本冲回证据。支付capture和sale、现金fee和经营fee是不同视图，不能双计。

事件键为(store,source_system,type,event_id)。完全一致重复导出保留母行及重复定位；同键有差异，只有明确版本链和快照才能选择有效记录，否则隔离冲突。无ID、同金额不能自动去重。不同系统必须有crosswalk才认同一事件。requested到posted若是同事件状态更新，不扣两次。

net_summary有成员/范围时默认只校验，不累加或再扣它内含的退款。只有汇总可用时选择aggregate-only分支，禁止叠加覆盖明细；缺少拆分证据不反推毛额或费用。

逐结果列纳入/排除/隔离ID及行数/金额覆盖。成本覆盖组H的收入、退款、成本必须相同对象范围；全量销售不能减部分SKU成本冒充全量毛利。费用需可归属、无重叠及完整范围声明；不明分摊不按收入比例猜。未列费用不是0，明确0也需范围依据。

## 3. 经营输出和禁推断

- 范围内商品净收入N＝去重已发生sale规范金额＋已发生refund规范金额。注明净折扣/税/运费范围，不能直接冒充某个Shopify报表字段。
- 覆盖组商品差额G_H＝同组净商品收入N_H−商品成本C_H。无独立冲回依据则不冲成本。
- 列明变动费用后的范围内贡献M_H＝G_H−费用净额F_H。只有成本和该费用范围完整才这样命名；否则降为“已列费用后片段”或unknown，并列缺项。固定费用/税/资本等未含，不称净利润。
- N_H>0且前述范围完整才可给M_H/N_H；N_H≤0不输出利润率。缺成本不抹掉已知净收入，但不得因此给全范围贡献。未解释现金差额也不自动导致已知经营片段失效。

输出不能给法定财报、可退款额度、增量收益、ROI或扩量结论。留存实验只有同对象/窗口/成本费用与退款成熟度可比后才能谈指标解释；有数字也不等于因果。

## 4. 现金只采用“有符号流量求和”

统一规范列cash_flow_signed：流入为正、流出为负，依据明确业务意义映射；下列示例是输入约定，不是所有平台导出通用符号。不能把raw负数再放入“减退款/减payout”的表达。本分支只有求和，没有再次减去规范化流出。

|type及语义|raw示例|cash_flow_signed|处理|
|---|---:|---:|---|
|capture：成功通道流入|+100|+100|只入现金视图|
|cash_refund：成功通道流出|−20|−20|不再减−20；若raw正绝对额且语义明确才转负|
|processor_fee：通道收费|−4|−4|收费流出，不与经营费重复计算经营贡献|
|processor_fee_return：通道费返还|+1|+1|独立返还分支，不把它当收费绝对额|
|payout：通道向银行转出|−130|−130|通道流出，不记销售，也不再减负数|
|adjustment：有证其他调整|依原定义|按有证方向|语义未知隔离，绝不简单abs|
|bank_receipt：银行到账|+130|不加入通道流量|仅按批次核银行到账；不是第二次通道收入|
|opening/closing：余额|0/7|不是流量|分别作起点与观察值，不累计作交易|

预计期末通道余额＝期初余额＋合格cash_flow_signed求和。未解释桥接差额＝观察期末−预计期末，缺观察值则无匹配结论。通道范围或流量缺覆盖时只能列已知流量小计/缺口，不把残差叫费用、亏损或退款。

逐payout匹配bank_receipt及其日期：跨期到账留在其到账期，不能提前计入。只给一批结算不证明完整银行现金；缺银行期初/期末和全部流量不能宣称整店现金已核清。经营E与现金C关系必须逐条解释未支付销售、跨期退款、费用、未结算、到账时差及通道外成本付款；无证差额保持未知。

## 5. 可读交付与撤证

实际报告依次给范围/来源→规范化与重复处置→净收入及覆盖组中间过程→全量未覆盖项→通道桥接与结算匹配→可说与不可说→一个最先补证动作。使用现有可靠本地计算工具复算，禁止只凭语言算术；不得安装新依赖。无法可靠算则保留原表与待核项。

计算精度与展示：保留来源金额的原值和精度，使用能无损表达输入的单位整数，或从原数字文本构造的十进制数计算；不把二进制浮点尾差当成业务差额，也不从浮点转成十进制后声称恢复了原精度。按输入合同执行必要业务舍入并记录位置与规则，其余中间值不为展示提前舍入。除法采用明确的计算精度，比率只在最终展示时说明保留位数与舍入方式，不用已格式化的展示数回算。币种/结算的最小单位与舍入规则须有适用依据，不能一律两位小数；缺规则只限制依赖它的结算或差额判断，保留可精确完成的材料金额计算。

撤去成本，则相关G/M/比率撤回，已知收入保留。撤去refund发生证据，该退款隔离，不继续给无条件净额。撤去费返还语义，相关费用及现金桥接受影响；不取abs补全。撤去期末余额，仅撤销余额相符结论，明示完整流量下的预计余额可保留。撤去费用覆盖声明，则贡献降为片段。仅针对真实缺口做最小复查，不建立考试题库。
