# 客服回复与人工交接：从这里开始

用新问题的低敏摘要和公开/自有非敏感商品政策，得到完整英文客服回复、中文理由、下一内部动作和交接JSON。不是只能看旧例子的练习包；也不是收件箱、发送器或订单操作工具。

## 先说明材料，再开始

先说明材料类型、来源、是否含真实客户或订单信息及用途，不先发敏感正文。确认可读后，只提供这一个问题的低敏摘要、适用商品/政策和输出位置；不必先填JSON或找客户原话。

可用：操作者明确指定且有权处理的公开商品/店铺FAQ、自有非保密且无个人或客户敏感信息的政策、非客户记录来源的问题摘要，以及新原创合成材料。真实客户原话、工单/订单及其摘录、改写或脱敏件，必须在打开前另找使用者确认；“有权处理”或换名为摘要不能绕过。账号/密钥、完整敏感标识及无关资料不要提供。材料类型不清先问元信息，不先读内容；具体门禁见[契约](base__support__原版方法__payload__references__input-output-contract.md#业务正文读取前)。

## 怎么委托

让现有Codex读取[客服方法](base__support__原版方法__payload__METHOD.md)及其必要引用，然后用普通话说明这一个组织/事项的目标。

> 请先按材料类型确认可读范围；通过后，依据我指定的问题摘要和政策起草完整英文回复、中文理由和内部待办。只保存审阅草稿，完整JSON保存到我指定的位置，不发送或操作订单。

政策标来源、适用商品/市场、版本及截至；不知道就说未知。缺订单不阻塞独立FAQ，缺政策不补造退款权利；摘要不冒充客户原话。来源与事实、假设分开。无需先判断专业类别或填完表格。

## 你会拿到什么

先看完整英文审阅稿，再看中文关键理由、待补信息与给定角色的下一内部动作。14顶层/19交接键JSON保留证据、时间线和状态，供回查，不要求用户先学JSON。准备材料不等于已经转交；无回执pending，ready_to_send=false始终保留。

有新政策、目标或事实时，先说明新材料性质，再续接同一事项；每轮交新全文和变化，另存结果保留首答。政策更新不自动证明适用于该事项，旧答不是新事实。
