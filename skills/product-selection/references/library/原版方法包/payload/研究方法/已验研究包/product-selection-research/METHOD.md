# 公司选品决策中枢

本包用于获准已有候选的有限离线研究。先读[中文入口](../../../../../00_开始使用.md)，按任务取用[主张准入与成熟度](references/claim-admission-and-maturity.md)和[来源与使用限制](references/source-scope.md)。当前成员见[文件清单](../../../../../CURRENT_MANIFEST.json)。包装不提升方法成熟度，不授予采购、真实经营或完整视频学习资格；日期未知课程不支持正式方法，本包不消费旧课程条目、学习卡、母本或158行索引。

## 目标

把“看起来会卖”转成“在指定市场、渠道、商业模型与风险边界下，是否值得进入下一轮验证”的证据化判断。

默认不直接输出“爆品”或最终 SKU。先产出有来源的事实、假设、缺口及最低下一证据；缺证时下一步是内部证据整理，不是询盘、样品或小批准入。只有相应硬门禁、阶段证据和动作授权均满足，才评估所请求的下一阶段。填写完整表格不证明商业可行。

## 先确认决策上下文

缺少以下信息时先列 `unknown`，不得擅自补成事实：

- 目标市场、平台、店铺/品牌阶段；
- 商业目标：爆量、利润、品牌、矩阵补位、清库存或内容带货；
- 可用供应链、最低订货量、交期、资金和最大可承受损失；
- 价格带、履约模式、合规能力、知识产权和素材权利边界；
- 用户已有的数据、候选、排除项与必须满足的条件。

如果用户只是问“有什么品”，可生成候选方向，但结论必须是 `candidate_only`。

先从用户已经给出的材料识别本次要作的决定：选择继续研究的候选、解释竞品差异、整理痛点，还是安排下一验证；不要让用户先选专业模型或补完整问卷。只询问会改变本次取舍且现有材料不能回答的关键缺项，其余保留范围内未知。已有候选的选择与补证顺序，调用[候选取舍与下一证据](references/decision-workflow.md#候选取舍与下一证据)；新目标或新证据到达时，调用[新条件下的接续](references/decision-workflow.md#新条件下的接续)。先交本次可用结果与关键理由，按任务展开既有决策卡；不把全卡填齐作为交付前置。

## 执行顺序

### Gate 0：授权与风险边界

1. 明确本次只是研究、建议、供应商验证还是已获准执行采购/上架。
2. 不因研究请求代替用户登录账户、发布商品、改库存、付费、采购或提交客户数据。
3. 涉及受限品、健康功效、婴童、食品、危险品、锂电、医疗、隐私、品牌/版权/专利时，先进入专项合规/IP 门禁。
4. 当前官方事实与来源经验冲突时，以目标市场当前官方资料为事实基线；效果策略保留条件分支。

### Gate 1：定义商业模型

先写一句决策命题：

> 在【市场/渠道】用【履约/内容/品牌模式】销售【候选方向】，是否能在【资金/交期/风险】内形成【目标结果】？

记录用户自述的模式与组合角色；铺货/精品/品牌或四类模型只是可选描述，不是效果等级。门槛来自本任务目标、证据和风险限制，不因选中模型名称而自动获得。

### Gate 2：生成候选池

候选可来自平台机会工具、搜索趋势、类目/榜单、评论与退货、关联购买、现有客户/供应链、内容趋势、竞品缺口和内部销售数据。

每个候选必须保留来源、市场、时间窗和“为何进入候选池”。榜单、热门词或 AI 推荐只生成候选，不直接评分通过。

### Gate 3：标准化证据

按 `references/evidence-schema.md` 建立候选证据包，区分：

- `official_fact`
- `first_party_observation`
- `observed_market_evidence`
- `tool_estimate`
- `ai_extraction`
- `analyst_inference`
- `source_opinion`
- `case_evidence`
- `method_hypothesis`
- `unknown`

记录指标定义、时间窗、市场、样本量、数据来源、估算方式和限制。来源不一致时不要强行平均。

AI 可在有授权的有限证据上辅助抽取、翻译、提问与提出解释。默认不启用批量 VOC 标注、模型置信分流或自动晋级；聚类/标签只作隔离研究假设。关键结论须回接原文、记录解释者和分歧；人工解释及多个模型一致都不等于真值或独立验证。无法回接时不用该条作决策依据。

### Gate 4：合规、安全与权利

在分析利润前先做：

- 平台禁售/受限/类目资格；
- 目标国法规、标签、认证、产品安全、召回和物流危险品；
- 商标、专利、版权、外观、素材和兼容性表述；
- 供应商资质与测试报告可验证性。

合规、安全或 IP 的关键证据不足时，主状态为 `blocked_compliance`；未知不等于违法。其他证据缺口同时列出，不得用高销量覆盖硬风险。阻断后允许内部缺口整理和注明缺项的受限算术，但不得据此生成采购、样品或小批准入结论。

### Gate 5：验证需求

以下是研究问题，不是已经验证有效的多信号评分模型；检查信号是否独立、可比及能否被替代解释。根据任务和数据可得性选择：

- 多时间窗：短期、完整季节/年度、可用长期；
- 多信号：平台搜索/购买、外部搜索、内容/互动、评论/退货、内部数据；
- 地域与语言：目标国家单独看，不按另一个站点比例机械外推；
- 持续性：区分长期需求、季节性、事件尖峰、平台补贴和单一达人爆发；
- 可解释性：谁在什么场景下为什么买，替代方案是什么。

先按信息产生阶段选证据：搜索、问答与社媒偏购买前；评论偏使用后；退货与工单偏故障/服务；第一方实验偏可验证行为。不同阶段不能把提及率直接互换。对有授权的有限评论/VOC 逐条回接原文、上下文、解释与争议；去重保留独立重复故障，不默认批量标签或准确率阈值。标签本可选且未证通用效度；低频安全问题不得被平均数掩盖。

Google Trends 只解释相对搜索兴趣；平台机会/榜单工具只解释其覆盖口径内的信号。

仅当重复购买假设会影响决策时，使用[复购证据分层](references/replenishment-and-supplier-evidence.md#复购证据分层)。

### Gate 6：判断竞争与可防守空间

同时看需求、有效供给、相关性与集中度：

- 头部品牌/卖家/商品集中度；
- 新品进入速度、价格带、评分/评论、上架时间、广告/补贴依赖；
- 同质化、可替代性、可复制性和价格战风险；
- 候选是否在功能、体验、信任、内容、供应链、成本或履约上有可验证优势。

记录以下问题及其证据/缺口；unknown 合法，不能为填满表格捏造：

- `capacity_range_and_basis`：先检查任务市场、产品形态、属性/变体、可比性和估计校准依据；无可验证方法时容量 unknown，不给数值区间或据此推进；
- `first_traffic_entry_and_test`：第一个具体搜索/内容/客户/渠道入口、验证方法和不可发现停止线；
- `competition_clock_vs_total_lead_time`：新品进入、同质化复制、价格/CPC 变化和季节窗口，是否早于打样、合规、生产、运输和上架总提前期；
- `why_win`：对可触达性、差异及反证提出假设；竞品成功、低竞争或我们的叙述不证明胜因，需目标任务的原始证据及获准受限验证。

只有“痛点存在 + 能解决 + 能证明 + 解决后仍盈利”才是可防守缺口。

### Gate 7：VOC 到产品定义

按“人—任务—场景—体验—原因—问题根因”拆解评论、问答、搜索、退货和客服证据。

把目标用户写成可验证的 `分群 + 触发场景 + 待完成任务 + 当前替代方案 + 未满足障碍 + 目标结果`。画像字段只在会改变产品、合规、价格、渠道或表达时保留；不要把虚构的单一人物当成市场证据。

可选功能研究标签（method_hypothesis，未证通用效度，不要求套用）：

- `must_have`
- `performance_driver`
- `delighter_hypothesis`
- `remove_or_avoid`

每个拟议功能分列已知事实、根因/属性假设、证据缺口、最低验证证据、成本与风险；缺证只写待验证问题，不填定稿尺寸、性能、接受度或规格。不要把评论高频词、人工共识或 AI 总结直接当规格。

产品定义至少写清：服务谁、在哪个场景完成什么任务；现有方案为何不足；数量、外观、尺寸、材料、结构、功能、兼容、包装和使用方式；成本上限；安全/认证/IP；短期验证目标和停止线。对复杂或高风险产品，AI 概念图只能作为沟通草图，必须进入工程、合规、样品和测试。

产品组合必须由共同用户任务、可复用能力和组合经济连接。每个候选注明入口、核心、复购、配件或利润角色；“相邻类目”本身不是扩品理由。

情绪、身份、赠礼或社会情境只能作为待验证任务，不得替代产品性能证据。涉及健康、心理、身体效果或脆弱人群的表达，必须有相称证据与专项合规审查，不得把恐惧、焦虑或疾病当转化按钮。

把购买前关注与购买后体验分开，检查承诺—开箱—使用—维护—售后的预期落差。VOC 需记录市场、平台、产品阶段和时间窗，并在条件变化后复测。不得从公开文本臆断健康、宗教、婚姻、收入、教育等敏感或不可证明属性；采集需满足授权、用途限制、最小化和保留期限。

用竞品做产品替代时，锚定相同用户任务而不是复制同一 SKU。补充 `same_job_evidence`、`root_cause_of_current_solution`、`substitution_acceptance_test`、`discoverability_path`、`performance_equivalence_or_advantage` 和 `compatibility_safety_ip_gate`；替代接受度缺失且会改变决策时保持 hold；硬风险未知用 blocked_compliance。候选标签不解除阻断，不定规格或自动 advance。

### Gate 8：单位经济与现金流

按 `references/decision-workflow.md` 做基准、保守和压力情景。至少包含采购、包装、头程、平台费、履约、仓储、税费、广告、促销、退货、损耗、长期仓储、移除/销毁、认证/质检、模具、汇率和资金成本。

利润为正但现金占用、最低订货量、补货周期或滞销尾货不可承受时，不能通过。

把利润与现金时点分开：按实际支付/到账事件递推银行余额，初始资金只计一次，保留无新增融资基线；净到账已扣费用、退款和预留不得再次扣除。毛/净额或扣款落点不明时先待对账，不生成可用净款。最低保留现金是阈值而非费用；缺项利润、期内时序不明的峰值现金按 `references/decision-workflow.md` 明示限制，不把支出小计当峰值资金或最大损失。

### Gate 9：供应链与履约验证

核对：

- 真实报价、MOQ、交期、产能和备选供应商；
- 样品一致性、质检方案、包装和运输；
- 尺寸重量、破损、退货和售后；
- 旺季/节日倒排与断货、滞销两端风险。

没有供应商证据时，不输出最终成本和可采购结论。

现成方案/改款只是待评估路径，不保证低风险或可采购；中高复杂产品还需工业/结构/电气/材料等专业可行性、BOM、原型和失效测试证据。供应商口头“无专利/有认证”不能通过权利和合规门禁。

涉及多个报价、样品或版本时，使用[供货证据同对象比较](references/replenishment-and-supplier-evidence.md#供货证据同对象比较)；不因此自动提高成熟度或取得采购权限。

### Gate 10：设计最小可逆验证

验证步骤是公司按风险设计的研究方案，不是课程已证实的固定升级阶梯。先选择能改变下一判断的最低证据，证据缺项可先做内部问题与证据清单；只有门禁及授权满足才选择原型、样品、用户访谈、合规预审、内容测试、落地页测试、现成方案测试或小批量试销。现成方案用于降低首次承诺，但仍需核对产品来源、经销/品牌权利、标签、质量、合规、包装和内容权利。测试需预先写出：

- 假设与成功/失败判据；
- 最大预算、数量、周期和负责人；
- 数据质量要求；
- 停止条件与下一步。

不得把点赞、播放、一次售罄或一次爆发直接当购买需求；不得为了“测试”绕过平台政策、操纵评价、伪造交易、滥用退货或冒充真实用户内容。

产品改良应保留旧版问题、批次、改动、测试和新批次结果。公开迭代只能真实说明已解决与未解决项，不能用小号评论、虚假社会证明或内容覆盖历史问题。

## 决策输出

不要只给总分。先检查硬门禁，再输出：

- `advance_to_supplier_validation`
- `advance_to_sample_test`
- `advance_to_small_batch_validation`
- `hold_for_more_evidence`
- `reject`
- `blocked_compliance`
- `not_suitable_for_current_business_model`
- `candidate_only`

使用 `references/templates.md` 的决策卡，明确：结论范围、支持证据、反证、关键假设、风险、未知项、下一步和停止条件。

主状态不能由低成熟度标签覆盖：合规/安全/IP 未过时用 `blocked_compliance`；已知不可接受或无法补救的失败可 `reject`；一般上下文或证据不足用 `hold_for_more_evidence`。多个硬失败全部显示，主状态选最能限制行动者并说明依据；`candidate_only` 只描述线索，不能解除阻断。任何 `advance` 都需要无硬阻断、阶段证据及对应动作授权。受限算术不是准入判断。

## 平台适配

通用主干不随平台变化；平台专属指标与权限见 `references/platform-adapters.md`。调用当天重新核验高漂移事实。

## 强制停止条件

出现下列任一情况立即停止推进：

- 目标市场、平台或商业模型不明，导致结论会实质改变；
- 禁售/受限/认证/IP/安全证据不足；
- 数据无法说明时间窗、样本、市场或指标口径；
- 利润只在乐观情景成立，压力损失超过授权；
- 供应商无法提供可验证报价、资质、样品或交期；
- 需求由单一达人、补贴、短期事件或可疑数据主导；
- 无法给出容量区间依据、首个流量入口或竞争时钟，且缺失会改变进入判断；
- 替代方案未验证用户接受度、可发现性、性能等价或兼容/安全/IP；
- 需要用户授权的采购、支付、上架、库存或真实客户数据操作尚未获准。

## 来源纪律

- 观察深度、发布日期准入、主张采用分列。当前 156 份教学资料发布日 unknown，只登记/历史研究，不作为正式方法依据；2 份系统文件非教学来源。官方当前事实仅支持对应机制，数学和权限规则有独立依据，经营效果仍需真实项目证据。
- 受限研究按主张准入表执行；旧来源卡中的历史“保留/净新增”不构成当前效力。本候选不携带或调用旧来源索引、课程条目、学习卡和母本；总体历史限制见[来源与使用限制](references/source-scope.md)，不得据摘要推定逐条采用资格。若任务要求使用具体旧课程，停止该采用分支，须另提供获准、安全、精确的来源与效力证据后重新判断；无重新观察或源删除授权。
- AI 可帮助提取、聚类、比较和发现缺口，不能替代原始证据或签发结论。
- 课程中的固定阈值、成功率、收益与平台算法说法默认不采用，除非有当前证据和适用条件。
- 不复制竞品文案、图片、视频、专利设计或受保护素材。
- 记录 `retain`、`refine`、`replace`、`branch_by_condition`、`reject` 或 `no_update_needed`，保留回接来源。
