# 账户健康、通知与售后

用于Amazon美国站获准材料的离线审阅、待办和未发送草案。先完成有证成果，再指出影响下一决定的缺口；不登录、不读取未授权的真实客户资料，不提交申诉、退款、赔偿或联系客户。政策依据核于2026-10-20，具体市场、资格、通知和使用当日的变化仍须核对。当前候选待独立复核，来源与未决边界见[政策证据映射](方法__provenance__K04_POLICY_EVIDENCE_20261020.md)。

## 先识别对象、事件和正在走的流程

从材料里提取市场、履约方式、offer/SKU/ASIN/订单/账户、关联标识、规则或通知日期、已发生/预告措施及用户要作的决定。多个对象分别保留，不能把一个offer问题扩大成账户已停用，也不能反向保证其他对象安全。

按事件选择：政策违规/AHR与ODR → 账户或商品通知 → 买家A-to-z/拒付 → FBM退款/RFS/SAFE-T → FBA退货赔偿。退款是谁执行、是否已经扣款、退货是否首扫/收到、是否已经提出索赔，是分路所需事实；缺一项只停止依赖它的资格或期限结论，先交事实时间线、材料草案和可核对的差异。

时间线每行记事件、对象、发生日/时区、来源与状态。要求、已申请、已批准、已支付、已到账分开。规则明确日历日、工作日或小时时按原单位；只写“天”的项目不自行转成工作日或补造日历算法。起算时刻/时区未给时保留未知，不虚造一个精确截止，也不以显示更新延迟认定措施已解除。

## 账户评级与订单缺陷

AHR衡量特定商城因其覆盖政策违规而停用的风险，范围0–1,000。绿色200–1,000的风险描述限覆盖政策；黄色100–199表示风险；红色99或以下可以是符合停用条件或已停用，必须以实际措施证据区分。无论分数多少，法律要求、涉嫌欺诈/规避或其他有害活动等仍可能立即停用。覆盖清单不是全部Amazon政策，也不改变各子政策要求。（C01–C03）

初始200及过去180天滚动说明可用于解释背景，不能由部分计分例子预测完整得分。核同一政策、严重度和重复历史，优先处理最严重事项。关闭/删除商品、提交材料、确认解决、移除违规显示、撤销重复计数及恢复销售不是同一件事。因AHR停用不能靠等180天保证恢复。

FAQ对所述Critical通知及达到同政策重复上限后描述三天处理期；这不覆盖前述立即措施例外，也不保证个案都有宽限。必须核通知的适用原因和起算，不能自造时区。英文恢复问答同时出现“100之上”和“100或以上”；恰100时不据分数判恢复，仍核未解决违规、申诉结果和实际恢复状态。（C02）

ODR用于卖家自配送订单，按60天窗口内至少有一种缺陷的订单数/同期订单总数计算；分子按订单去重，不把负面反馈、A-to-z和拒付事件简单相加。核一致的订单日期与统计窗口，不用AHR180天替代。政策要求低于1%；高于1%可能影响FBM权限或特定高缺陷商品，恰1%也不满足“低于”，但任何数值均不证明措施已经执行。（C04）

按同一观察时点逐订单核对以下状态；先核与该事项明确对应的排除或已生效的申诉结果，再判是否有至少一种仍计入的缺陷，不能只凭“已退款”“已取消”或“已申诉”排除。（C04）

| 缺陷类别或状态 | 本次ODR计入判断 |
|---|---|
| 1/2星卖家反馈 | 计入对应订单；商品星级不是卖家反馈。买家撤回的反馈不计，平台显示可能延迟；该单若另有仍计入的缺陷，订单仍计一次。 |
| A-to-z有过错且获批 | 计入对应订单。 |
| A-to-z索赔提出后卖家退款 | 计入对应订单；退款本身不消除该索赔对ODR的影响。已证明适用的无过错、拒绝、撤回或特定流程排除仍按对应记录处理。 |
| 因订单取消引发的A-to-z索赔 | 计入对应订单，仍核对应排除；普通取消订单本身不自动成为ODR缺陷，也不能把取消率与ODR混算。 |
| 已计入的A-to-z正在等待申诉决定 | 继续计入，不能把提交申诉当成已移除。 |
| A-to-z无过错、索赔被拒绝、撤回，或属于特定人身/财产损失流程 | 按匹配的证据排除该A-to-z事项；不得扩成该订单的其他缺陷也被排除。 |
| 申诉推翻原决定并认定无过错 | 按对应结果移除该A-to-z缺陷；若同单还有有效负面反馈或服务性拒付，仍是缺陷订单。 |
| 服务性拒付且发卡机构判买家有利 | 计入对应订单；只知道“发生拒付”但未明确类别/决定时，不猜该方向。 |
| 欺诈性拒付 | 不计入该拒付事项；同单其他有效缺陷仍另核。 |

对证据足够的状态直接给有依据的计入或排除，不把已经明确的事项一律留为unknown；对缺失、冲突或尚不能定位的状态保留具体未知及其分子影响。按订单日期归入同一统计窗口；反馈、A-to-z和拒付同单去重，展示计入订单集合、排除依据及算式。不把报表显示延迟当作法律/平台状态自动改变；报告刷新时刻未提供则不补造。比率与平台已经采取的措施分开，不据超阈值宣称账户或FBA已停用。

## 通知与申诉草案

先交事实时间线，再分别写已证事实、解释假设、已完成纠正及凭证、拟采取预防措施、未解决事项和下一验证。覆盖通知明确列出的对象；发票/认证/检测、根因和已整改不得虚构。需要问卷、确认、测验或文件时按通知分路，不能套通用“保证解封”模板。平台“两天反馈”说明不是卖家统一申诉截止；近365天发票要求只在相应类型需要时使用。（C05–C06）

未发送草案直接写成可审阅内容：说明收到何事项、哪个对象、发生了什么及依据、哪些原因已确认/仍未知、已做什么且凭证在哪里、下一步如何验证和防止重复；没有完成证明的动作写拟采取，不写已全部解决。随后给需补的最小材料和下一动作，不只交空模板。

## A-to-z和拒付：分开每个计时事件

先确认卖家直接配送争议，Amazon Pay、人身/财产损失等使用各自规则。一般买家消息/退货请求的48小时要求、部分24小时建议与平台调查的信息请求不同；存在自动处理例外，不保证所有买家情形都有同一等待期。（C07）

| 事件 | 可核对的规则 | 草案与停止点 |
|---|---|---|
| 亚马逊调查要求补充信息 | 信息请求后72小时回应 | 配送争议准备追踪/交付证明，退货争议准备退货标签、处理及沟通证据；具体日期/时区仍以请求为准。（C08） |
| 买家索赔获批并向卖家扣款 | 30日历日内提出申诉，提供新信息；申诉中的追加信息请求仍为72小时 | 分开初次回应和决定后申诉；结果体现最多7日历日不是现金到账或成功保证。（C09） |
| 信用卡拒付 | 核发卡机构/亚马逊实际请求及服务性/欺诈性类别 | 不套A-to-z或SAFE-T时限；缺具体请求可先作事实及凭证草案，停止精确截止和责任断言。（C04/C10） |

C07某类“退回后5天未退款”的自动批准条件不替代FBM退款处理义务；无法送达/拒收/退回卖家的某些自动退款另有不影响ODR的限定。每项回到具体分支，不以一般描述覆盖例外。

## FBM退款、RFS与SAFE-T

先核退款执行方、预付标签计划、是否RFS首扫、是否已部分退款、退货收到/妥投证据及退款扣款事件。合格且自动批准的Amazon预付退货标签在指定承运人接收首扫时可触发RFS；买家自行寄回、卖家自购标签及已部分退款等不直接套这个分支。运输丢损先核承运人责任与适用索赔流程。（C10–C12）

自2026-01-26，已批准的Amazon预付标签计划中尚未触发RFS的对应退货，收讫后处理窗为4日历日；不是所有退款统一等4天，也没有取消RFS。超时自动退款通常影响SAFE-T资格，但非妥投/未收到、错误原因代码退货运费等例外须核。C10的旧两工作日/48小时描述不在这个更新覆盖分支继续作为任选标准。（C12/U02）

SAFE-T先核是否属于Amazon代退/RFS或适用客服计划、免费换货等合格情境、是否非卖家过错以及排除；自行退款、A-to-z、FBA、拒付、承运中丢损等不能因有损失就自动纳入。特定错误退货原因代码的运费例外不泛化为所有自行退款可赔。（C12）

| 事项 | 核对办法 |
|---|---|
| 申请长度和起算 | US更新自2026-02-16把申请窗从60改30天；处理中申请按公告例外。主政策按退款扣款/免费换货收到退货表述，更新公告另按退货到仓扫描与退款较晚者、某丢件最后扫描表述。先匹配具体计划、事件和资格；两口径产生不同结果时列出带出处的两个计算，最终起算记未核，不选择较宽日期放行，补当前适用通知/官方说明。时区/确切截止缺失不补造。（C12/U01） |
| 最早提交 | 有退款、有效RMA等条件下的“至少等15天或收到商品”按适用分支处理；不要删掉“或”，不要把等待期加在30天截止之后。资格排除优先于时钟。（C12） |
| 补件和申诉 | 调查补件7天；决定后7天可申诉一次并提供新信息/证据。以实际给出的日期时间核对，不把状态更新24小时作为延期，不把每订单一次索赔与一次申诉混为一个状态。（C12） |

能确认的资格及凭证先形成未提交材料：争议退款的对象与金额、退款执行方、退回物状况/差异、对应证据、所请求复核事项和仍缺条件。不能确定起算的分支仍交这份完整材料和时间差异，明确“暂不能确认是否在期内”。不得保证赔偿或为了好评退款。

## FBA买家退货与赔偿

FBA买家退货由Amazon处理，通常收货后30天请求退货，品类/节日可能有例外；这是买家退货条件，不是卖家赔偿申请期。核实物退回、可售/不可售、责任及已处理/已赔偿，别把退货请求当已收到物品。（C13）

买家退货赔偿先核FBA一般资格和特定责任/排除。按事故发生阶段区分，不能把订购前成本基准套到订购后买家退货。赔偿可能是同款替换或款项，找回或误赔可能撤回；申请、批准、发放及到账仍需各自证据。（C14–C15）

| 事件 | 可核对的规则与限定 |
|---|---|
| Amazon已代卖家退款或换货的FBA买家退货丢损 | 对应申请窗口为退款或换货后60–120天，先核是否已处理或已赔偿、具体责任及排除；不能重复申请或把别的库存丢损塞进此窗。（C15） |
| 退款后60天仍未退回 | 有通常向买家收费并赔卖家的分支，但存在不退货退款/责任等例外；不保证自动收到款项，也不把等待自动处理当无限延长申请窗口。（C15） |
| 已发放赔偿的估值异议 | 从赔偿发放起60天；这不是全部资格拒绝的统一复议期限。其他拒绝以具体决定及适用规则补证。（C14） |

买家损坏的一般排除与残损费的特殊分支同时核，不写成一律赔/不赔。召回、缺陷、违规、卖家自行退款等排除按相应规则处理。非买家退货阶段、空退款标题下未见内容及未取得的拒绝复议期限，不在本方法自行补齐。

## 把处理流程落到完整对账与下一动作

按同一订单/退货/退款/赔偿关联键并排核销售数量和单位、请求/授权、实际退款、实物回收与品况、赔偿申请/批准/支付/到账。金额或实物不一致先列事实差异，不能直接判欺诈、平台欠款或运输商责任。已入净销售的退款回接03核对不再扣；请求不入实际费用，待赔偿不算现金。成本缺项列未知并传给贡献方法。（公司对账方法，沿用03）

交付顺序：主要判断及所需完整内部草案 → 每个关键时限的触发事件/规则/日期依据与未知 → 对象对应的金额和实物差异 → 一个最值得先做的核验动作。无关商品和有证成果继续有效。资格、安全或未处理通知影响的对象先停止推荐扩量；广告ROAS不能覆盖该限制。

材料变化时只更新对应对象/事件及其依赖：提交回执不等于解除，新的退款记录不自动改现金，撤回证据使依赖结论退回未知。保留原材料与前版，不补造已发生动作。最终始终是待人工审阅和另行授权执行的成果。
