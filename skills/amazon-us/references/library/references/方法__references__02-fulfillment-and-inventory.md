# 履约、库存与承诺审阅

公司候选方法，以输入记录判断事件；不是Amazon后台状态字典。平台职责的历史参照为[FBA总览](https://sell.amazon.com/fulfillment-by-amazon)、[FBM总览](https://sell.amazon.com/programs/fulfilled-by-merchant)及[库存概览](https://sell.amazon.com/learn/inventory-management)。FBA本轮响应未展示所需正文，FBM/库存未重开；分别保留2026-09-05/06原观察，首次发布日期未知，正式采用待决。

## FBA：逐事件而非单一“已入仓”

从商品/销售单元/包装数量开始，建立SKU与批次范围。将准备、运输交接、接收和各库存状态按各自证据时间列开。核数量前先对单位：箱、销售盒、单个物件、订单不同。资料已校对不能代表实际点数/装箱，愿意接收不能代表收讫。

发出100销售盒、接收80时，只能在同批同单位证据下列20待解释；没有丢失证据不能直接索赔。平台可售/预留/不可售若仅为输入声明，标来源，不替平台认证。库存状态子集可能重叠；只有输入明确互斥且同快照才能相加。缺可售记录不是0，也不能单凭仓存判stranded。库存老化需时间和需求证据，销售速度需相容窗口；未齐就不计算days-cover或补货量。

输出差异队列：对象、单位/数值、两个事件及时间、未知原因、最小凭证、拟负责角色。给取证/检查草案，不生成货件、标签、移除或补货动作。当前入仓UI和具体资格仍是缺口。

## FBM：容量、截止与运输分开

核可用库存和订单数量单位，既有队列必须占用产能。按输入的营业日历、截止规则和先后顺序推算最早可处理时间，区分排程假设与已经完成。不得把面单打印当交承运；只有交件/首扫证据才支持相应事件。

给运输所需时间与客户承诺的比较。日历、时区、线路或承运证据缺失时不造送达日期；产能不足可以交调整承诺/处理队列的待审草案，不自动通知顾客、修改后台或购买面单。特定平台时限和履约处罚需要当前合格政策证据，不能从一般职责推定。

库存或履约存在关键未知时把影响传给[广告](方法__references__05-sponsored-products.md)与[现金](方法__references__03-contribution-and-cash.md)，不把“有库存”当全部经营准入。
