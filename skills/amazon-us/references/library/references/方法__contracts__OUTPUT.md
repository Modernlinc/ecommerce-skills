# 输出约定

开头写清报告日期与材料截至时点、版本、对象范围、合成/实际边界以及一句主要结论。整体选择 DRAFT_READY（仅草案可审）、NEEDS_EVIDENCE（具体决定待证）或 BLOCKED（关键任务无法安全成立）；各分路可不同。不用状态掩盖缺失正文。

完整经营报告必须有：
1. 商品/offer/经营模式与供货证据结论，具体冲突与能先写的事实草案。
2. FBA/FBM单位、数量、事件、能力、承诺及责任差异；条件时效与未证边界。
3. 收入桥接和费用逐行解释、是否已含/重复、已知小计、最终未知、独立现金及未结算项；公式可复算。
4. 通知事实时间线、作用对象/合成截止、已做/拟做纠正草案、退货/退款/赔偿/实物对账、根因假设及反证。
5. SP资格、结构草案、逐搜索词/产品目标相关性与样本、变更对象/理由/条件/停止，接回贡献、库存和通知限制。
6. 一个最高优先下一动作、需要的最小证据、谁审和再看什么；其他待办可并列但不伪造责任接受。
7. 输入行和来源定位、未知/未读/日期及真实平台停止点。

用户只要局部报告时按任务提供相关完整部分，说明未请求的部分，不强行补空章节。对整体报告缺一分路必须诚实列未完成原因，不能缩减能力后宣称整包完整。

金额至少同时给出公式和行号；不同窗口不能静默混加。将“累计已知支出/已知小计”与“最终贡献/净利润/可用现金”分开。退款、赔偿申请和广告归因销售不能直接当结算收入。

草案必须完整可读：具体对象、建议文字/变更、证据、受影响范围、前提和停止。不得输出可直接上传的平台批量表/API请求或声称已发送/创建/启用。数字示例和合成通知不能证明政策、业务效果或真实账户。

多SKU改稿时，让每项拟写声明能回接适用SKU和相应证据；共用稿与各SKU差异稿分清。不能用于某对象的声明及缺证原因留在内部审阅备注，不混入消费者正文。无关字段和有证对象照常交付完整文字。

## 查询与历史样本局部报告

在相关经营部分之外，给出：
- 原查询/对象/报表/期间，原数及可复算份额；矛盾或缺证行单独隔离，不能静默修数。
- 能支持的阶段线索、主要假设及替代解释、区分它们的最小下一证据；份额不贴绝对CVR或因果标签。
- 当前/历史各自出处与选择理由，查询采用/待核/排除、TopN覆盖限制、季节性未知；去重集合不称独立人数。
- 依据已给商品事实的完整待审标题或要点及修改理由；确实缺功能证据时具体指出哪一句不可写，而不是只交空模板。
- 一个最高优先下一动作，回接供货、贡献、现金和通知等实际限制，写清审阅、执行和停止边界。

这些增项不替代整体经营报告的原七项要求。新任务不得把旧样例OUTPUT当首答；一次合成使用只能证明本次输入下的行为，不能证明真实经营效果、任意宿主或自动写入链路。

## 后续回合的交付

先给本次结论与变化理由，再交当前请求范围内完整可用的修订正文或可复算结果，最后给一个下一动作。若原稿仅局部改变，涉及的标题/要点、内部回复或算式应在本轮可直接取用，不要求用户从多轮差额自行拼稿；用户要求整份更新报告时，合并交付当前完整版本。

只展开新证据直接或间接改变的部分，指出仍有效且影响使用的继承条件；不逐回合重贴原七部分、全部来源及停止清单。日期逐记录回接，不给没有时点的记录统一补截至日。重要单位、金额口径、声明条件及现实操作边界不能为了简短删除。消费者正文与内部审阅备注继续分开，未知只阻断依赖它的决定。
