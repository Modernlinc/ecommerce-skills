# Meta 广告结构与声明式草稿

## 三层责任

| 层级 | 必须明确的决策 | 不得混淆 |
|---|---|---|
| Campaign | 业务目标、广告目标、预算归属方案、最大测试损失、特殊广告类别待核验 | 不在此层假定素材赢家或真实交付 |
| Ad Set | 优化事件、转化位置、受众约束、placements、排期、竞价／预算（如由此层承担） | 计划设置不等于实际分配；自动扩展或版位会污染对照 |
| Ad | 身份引用、素材版本、文案、CTA、目标 URL、追踪参数、权利与主张证据 | 不把广告文案当成 Offer、价格、库存或页面事实 |

三层结构以 2026 年 2 月官方学习资料及既有资产作带日期基线；2026-09-04 的公开页面刷新受登录墙阻断。涉及当前按钮名、可选目标、预算模式、竞价字段、默认设置、资格或 rollout 时标记 `NEEDS_RESEARCH`，不得猜测。

## 从零素材到初始方案

需决定阶段、受众、预算分配或自动化素材首批时，结合[FB-2—6条件选择](payload__候选正文__Facebook广告运营Skill__meta-facebook-ads-operations__references__stage-audience-resource-playbook.md)。本节三层关系、budget_owner_level、权限与未知分层保持；不另套固定组数。

适用 plan/draft：用户尚未指定结构，希望由目标、商品与素材形成初始方案。以下是公司离线决策方法候选，不是平台最优结构、当前可选字段或效果保证。依据和限制见[来源说明](payload__候选正文__Facebook广告运营Skill__meta-facebook-ads-operations__provenance__SOURCE_NOTES.md)的“S1公司方法整理”；运行时不依赖私有方法卡。

### 先解释这次的零数据

指出究竟缺什么：整个业务没有付费观察、仅新素材无历史、还是已有业务换了一个待测问题。新账户不等于没有业务证据，新素材也不等于要推翻有效旧基线。没有历史投放时，第一阶段是把有据候选准备成可核的学习计划，不是选赢家。若已有可靠基线则保留它，本节不授权迁移或替代已有限定的迁移审阅规则。

从商品/Offer、市场与语言、业务目标、素材说明和资源/损失约束启动；页面或某项规格未定时，只暂缓对应承诺、素材或最终搭建，不把整个素材整理停掉。业务目标、拟议平台目标和实际平台配置分别表达；当前目标/字段可用性未核时用一般业务语义给计划候选，具体配置保持 UNKNOWN 并列 NEEDS_RESEARCH。

### 把素材变成可讨论的概念与问题

逐件保留素材编号、实际内容/观察深度、版本或父素材、商品和主张依据、格式/语言、CTA与页面承接、可用或暂缓原因。只有文字说明就只评说明，不声称看过像素、声音、节奏或素材已通过视觉QA。

“概念”是围绕一个用户任务、主要主张及证明方式的表达假设；“变体”是同一主要假设内可辨识的局部表达变化。按内容说明它改变什么、保持什么：
- 只改标题措辞、画幅、裁切或载体且任务/主张/证明未实质变化，通常作为同概念的局部变体或用途适配，不把文件数量当概念数。
- 用户任务、核心主张或证明逻辑实质不同，可分成不同概念；同一产品或同一格式不能证明同一概念。
- 同时变多项并不自动成为一个有效的新概念，也不能归因于某一项；内容不足先做暂定关系并写理由，保留待核，不强行去重或删除。
- 无新增信息的重复不占首批独立假设名额；不同版位适配可有实际用途，但不冒充新的市场需求或证明效果。

为每个保留概念写一个当前问题，以及支持、反对/未知信息和最小核对。没有反馈资料时也能基于已给商品事实提出原创表达假设；不得编顾客证言或市场代表性。创意概念分组是内容组织，不自动等于 Ad Set 分组。

### 先取舍，再生成三层结构

先列本轮要解决的主要问题及必须共享/必须分开的条件，再决定对象数量。以下是选择理由，不是固定配方：
- 相同业务目标、市场/语言、转化承接、Offer和需要共享的受众/排期条件下，仅比较表达概念时，可把它们放在同一拟议交付单元内的不同 Ad；管理较简洁，但实际曝光可能不均，不能据未曝光或少花费宣布落败。
- 受众约束、转化承接、排期或观察预算需要独立控制且有明确业务理由时，考虑不同 Ad Set；同时说明增加单元对资源分散、重叠和可比性的代价。为了看见每个概念而拆组只是候选，不能保证等额实际交付或随机对照。
- 只有业务目标或其他需独立管理的活动级约束实质不同，才考虑分 Campaign；不因新文件、新画幅或一个概念不同就自动分活动。当前字段能否实现仍待核。
- 资源不足以完成多问题的有意义观察时，选择证据更贴近当前任务、制作与复核成本可承受的首批，其余具名暂缓，并写进入条件。顺序批次可减少同时管理负担，但时段变化也会削弱比较，不能宣称更干净因果。
- 没有有权且适用的存量名单/种子证据，不凭“漏斗完整”补造再营销或类似受众；仍可提出不依赖名单的内容与受众任务假设，具体平台设置待核。

输出最终推荐及实质可行备选，并说明何种输入会使决定改变；不为凑备选列无关方案。不要求用户先给正确分组。没有当前字段证据不妨碍这种业务层面的离线取舍。

### 预算归属与初始资源计划

对方案分别写总讨论上限、愿承受的最大贡献损失、非广告可变成本/产能、拟计划值和真实花费权限；使用下节既有 budget_owner_level，不改名。
- 若主要目的在共享目标下让多个合格单元竞争分配，可讨论 Campaign 归属候选；代价是单元可能观察不足，不能把算法分配当方法胜负。
- 若本轮需要具名单元的观察额度和审阅责任，可讨论 Ad Set 归属候选；代价是管理与碎片化，且计划额度不等于实际花费或公平分配。只有一个拟议 Ad Set 时不凭层级名称宣称策略更优。
- 在显式资源约束下可以给具体首批数量、计划金额和排期，并解释推导与替代；这些是本例离线计划，不是行业阈值或当前平台最低合法值。未知的预期行动成本不能用行业均值补齐，也不能把具体计划值冒充预计效果。
- 所有并行与顺序计划累计不得超过同一总上限。最大损失不自动等于花费；按[经营公式](payload__候选正文__Facebook广告运营Skill__meta-facebook-ads-operations__references__business-math-and-unit-economics.md)作明示情景。缺收益证据时可用明确的零回收保守情景约束首批，但仍需纳入已知额外成本；不能保证运行中恰好到线停住，潜在延迟和未结成本需留余量。可论证额度不足时先收敛问题或暂缓付费实施，不取消可交的离线方案。

### 新资料到人工搭建的准备合同

先按[读前准入](payload__候选正文__Facebook广告运营Skill__meta-facebook-ads-operations__references__permissions-and-live-gates.md#打开资料前的准入)核范围，将来源版本、商品/Offer、页面与每项素材编号关联。真实已准入来源中的商品规格、市场/价格/适用条件标supplied_fact及未核范围；合成条件仍为project_hypothesis，官方平台事实与实际任务许可按入口类别另列。不因广告准备需要补造卖点、价格、供货或顾客证言。只有素材说明就只评说明；原画面/音频没有合法可读证据时不签视觉QA。

对本轮所选广告交完整可用正文、标题、CTA和目的地；未制作的素材交具体brief（任务、主张与证据、画面/镜头或版式、文字、需制作资产、禁止变换和验收点），不能用“待写文案”交差。用本地ID表达归属，不用伪造真实ID。身份可写待由业务负责人选择的Page/账号条件，目标/事件/版位以有据建议加实施核验项表达，不把未知配置填满整张表。

累计资源按当次币种/周期、额外成本、损失及储备重算；旧50美元只是示范。商品、页面、市场、资源或权利改变时更新受影响对象/版本、重算资源、重建URL，保留仍有效稿件与明确的暂缓项。最终按[人工搭建交接](payload__候选正文__Facebook广告运营Skill__meta-facebook-ads-operations__references__commerce-completion-workflows.md#人工搭建交接)让接收人无需拼历史即可使用。

### 具名草案、首批与后续

先形成一份“拟议意图”：每个 Campaign 的业务任务、每个 Ad Set 的共同约束/主要问题、每个 Ad 的概念与素材归属，以及选择理由/备选/待核。它来自简报与明确假设，不是从已生成指针抄回的答案，不冒充用户批准意图或实际配置。

再生成具名 Campaign—Ad Set—Ad。每条拟议 Ad 有素材编号和版本、可用正文、标题、CTA与承接；确需后续制作/补证的项交具体brief并说明未完成部分，不输出只有 UNKNOWN 的空表。所有拟议对象均 PAUSED、exists_in_meta:false、published:false，actual_delivery:UNKNOWN；多对象遵守下文M2，显式本地 namespace、draft_id、parent_draft_id，并独立与先写的拟议意图核对。若任务是审计既有结构，仍必须取得独立既有意图，不能套用“新设计”路径自造正确归属。

给首批/暂缓清单，每项有目的、进入条件、检查或调整点。先核事实/表达/页面连续和计划可解释性；之后若另有合法实施，再看实际交付、测量及成熟业务结果。没有历史结果仍可完成前一阶段，不把当天点击、单一CTR或文案偏好写成赢家。平台选项、权利、测量和真实执行未核项只阻止相应交接，不阻断已具依据的文字与计划。没有可证异常时最早可信断点写“尚无已证异常；当前主要未知为……”，不要编故障。

## 预算方法的 Meta 适配

`META-METHOD-BUDGET-01` 在本层只保留 Meta 特有部分：

- 预算可能归属于 Campaign 或 Ad Set，必须在草稿上显式记录 `budget_owner_level`，不能同时隐式生效。
- 预算计划分别记录归属层、类型（daily/lifetime候选或UNKNOWN）、金额、币种、适用周期/排期与时区；引用上层值时明确继承路径。未知金额和平台最低合法值不代填；花费授权上限、最大损失、计划预算与实际花费分开，0花费授权不是平台合法预算。只有依赖未决预算字段的配置/执行动作停止。
- 预算、竞价、受众、placements、创意供给和优化事件共同影响交付与学习；变更后建立新基线，不直接沿用旧因果结论。
- `planned_delivery` 与 `actual_delivery` 分开；没有账户回读时 `actual_delivery` 为 `UNKNOWN`。
- 不保留固定预算比例、固定 CPA 倍数、固定观察天数或通用“每周事件数”。

单位经济、可承受 CAC、最大花费与最大测试损失使用本 Skill 的 [业务指标与单位经济](payload__候选正文__Facebook广告运营Skill__meta-facebook-ads-operations__references__business-math-and-unit-economics.md)。跨平台公共合同只可补充模式、输入和权限背景，不是经营公式来源。缺少公式要求的事件、订单、退款或成本输入时输出 `UNKNOWN` 或 `NEEDS_RESEARCH`；情景计算不产生预算授权。

`budget_owner_level` 是既有合同字段，不能改名为 budget_owner_proposal 等近义键。只有建议时，在具名建议层使用该准确字段并说明依据、适用条件与待核项；当前事实层缺证仍为 UNKNOWN。用户偏好不等于当前账户配置；无论采用正文说明还是结构化建议层，都不能让计划归属、实际配置和花费授权互相覆盖。

## 受众、版位、素材与页面一致性

对每个草稿保存：

- `audience_hypothesis`：只写可观察假设，不把兴趣、类似受众或自动扩展当成人的固定属性。
- `planned_placements`：Advantage+ 或手动的计划选择；当前可用性需官方或账户级刷新。
- `creative_placement_fit`：不同版位所需比例、时长、字幕和安全区的待核验项。
- creative_transform_contract：任务要求固定素材/文案时，登记原版本、已批准的变换范围、拟保持的控制、实际配置证据与逐版位预览待核项；动态组合不作为自动文字改写、裁切、生成扩展或其他增强的等价状态。未核实不得声称已关闭或已保持保真，也不默认永远关闭全部自动化；无法保持本任务批准范围时停止相关交接，不自行改图或操作账户。
- `offer_contract`：受众承诺、价格／资格、商品事实、页面首屏、结账和履约必须一致。
- `rights_and_claims`：人物、音乐、商标、证言、健康／收益／身份主张逐项有证据；缺失即 `NEEDS_FIX`。
- `actual_delivery`：没有授权回读则为 `UNKNOWN`，不以计划值替代。

Reels 页面在 2026-09-03 控制器刷新时可读，支持“placements 在 Ad Set、创意在 Ad”的层级边界；本轮 2026-09-04 再刷新被登录墙阻断，因此只保留带日期证据，不声称当日重新确认。

## 本地引用完整性（M2）

以下是公司离线草稿规则，不是 Meta schema；[M2来源与设计边界](payload__候选正文__Facebook广告运营Skill__meta-facebook-ads-operations__provenance__SOURCE_NOTES.md#m2)记录内部依据、假设与停止线。本便携候选字节尚未独立验收，不继承历史准入。

- 单一纯嵌套草稿可用容器路径表达归属，无需额外录入 ID。多个对象、扁平导出或跨文件引用时才显式标明本地 namespace、当前草稿集合内唯一的 `draft_id` 和非根对象的 `parent_draft_id`；跨文件先确认集合边界。`UNKNOWN` 是缺失状态，不能当作可解析 ID，也不要求全公司全局唯一。
- 先查存在与类型：Ad Set 的父为 Campaign，Ad 的父为 Ad Set；引用必须在集合内可解析。重复 ID、指向不存在的父或父类型错误属于确定结构缺陷，输出 `NEEDS_FIX` 并指出具体对象/字段。
- 再独立查意图：沿父链得到拟属 Campaign/Ad Set，与可定位的简报、计划或容器归属核对。父存在且类型相同仍可能错挂；有证据的归属冲突为 `NEEDS_FIX`。不得从当前指针反向生成正确意图。无意图证据只能说“结构可解析，业务归属意图 `UNKNOWN`”；缺失引用值为 `UNKNOWN` 或 `NEEDS_RESEARCH`，不同于已知的悬空引用。
- 未知只阻断依赖该关系的汇总、比较或完成声明；先请求本地归属澄清，不自动重挂、补造父对象或索取真实 Meta ID。本地 ID、可解析关系与 `PAUSED` 都不证明对象在 Meta 中存在，也不授权创建、改预算或发布。

## 离线交接语义核对

字段表与载荷引用同一份本地计划；对目标/优化事件、预算类型与口径、排期/时区、受众与语言、版位/身份条件、素材版本/变换/文案/链接逐项标明已映射、明确继承或有理由排除。缺失、重复键、条件被丢弃或相互矛盾不得静默补默认；引用关系继续按M2独立核对。质量状态、外部动作授权和未创建/未发布等是本地控制元数据，不冒充Meta参数；下游合同无法表达时说明不兼容，停止机器直接交接，保留可读离线计划。

## PAUSED 声明式草稿

下面是离线输出合同，不是 API 请求，也不代表 Meta 中已有对象。示例仅表示同一容器中的一组 Campaign—Ad Set—Ad，归属由这项单组声明表达，不额外要求 ID；不得直接复制成多组或扁平导出后仍省略引用。真正单一嵌套结构也可直接用容器路径：

```yaml
runtime_status: DRAFT
platform: meta_facebook
authorization_level: L0_OFFLINE
campaign:
  object_state: PAUSED
  exists_in_meta: false
  published: false
  objective: UNKNOWN
  business_goal: UNKNOWN
  budget_owner_level: UNKNOWN
  maximum_test_loss: UNKNOWN
ad_set:
  object_state: PAUSED
  exists_in_meta: false
  published: false
  optimization_event: UNKNOWN
  audience_hypothesis: UNKNOWN
  planned_placements: UNKNOWN
  planned_delivery: UNKNOWN
  actual_delivery: UNKNOWN
ad:
  object_state: PAUSED
  exists_in_meta: false
  published: false
  creative_version: UNKNOWN
  rights_status: UNKNOWN
  destination_url: UNKNOWN
approval:
  owner: UNKNOWN
  live_action_authorized: false
stop_conditions: []
readback_fields: []
```

事实输入缺失保持 UNKNOWN，不以建议补造。plan/draft 可以另列具名的 proposed_value、依据、适用条件、validation_needed 和失败停止/备选；建议不覆盖事实层，也不等于当前平台可选、已经配置或获得授权。版位建议须与素材和身份条件一起说明；无法提出有据候选时明确未完成的决定。未知只阻断依赖该缺项的结论或动作，不阻断独立且有据的业务分析。任何真实创建、预算写入或发布仍须 HUMAN_GATE_REQUIRED。
