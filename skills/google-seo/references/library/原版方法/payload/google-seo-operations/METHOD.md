# Google SEO 运营

## 当前使用范围

从[中文入口](../../../00_从这里开始.md)开始，适用范围与未证事项见[能力与来源](../../../03_能力与来源.md)，成员身份见[包清单](../../../MANIFEST.json)。这是离线文档方法，不是自动爬虫、改站或效果保证；不因封装继承全域通过。

内容更新/改稿读取[工作流](references/workflow-and-templates.md)§4、§5；标题差异也在该工作流，不要求先读旧验收档案。国际化读取[I1方法](references/international-implementation.md)，按能力说明的载体与证据范围使用。普通迁移、商品字段、Local与付费链接属性仍只采用[来源登记](references/source-register.json)的具名命题。实际稿件、技术状态及外部结果分别验收；未证分支、具名停源和原权限保持。

## 选择任务模式

- `teach`：用中文解释搜索系统、判断顺序、证据边界和常见误区。
- `audit`：审查用户提供的站点、页面、导出或说明，区分观察、推断、未知与风险。
- `plan`：把业务目标、市场、查询意图、页面、测量和损失边界转换为优先级方案。
- `diagnose`：沿“发现 → 抓取 → 渲染 → 索引 → 呈现 → 访问 → 业务结果”找第一处可证明的异常。
- `draft`：生成页面 brief、信息架构、技术修复单、内容更新、实验或委托取证草稿；不表示已在真实网站或账号执行。

多模式默认使用 `audit → diagnose → plan` 或 `audit → plan → draft`。详细字段与模板见 [工作流与模板](references/workflow-and-templates.md)。

先从已有目标与材料判断本轮页面要解决的读者任务和最重要的 SEO 决定，再选内容、技术、国际化或报告方法。下列开始前清单按本轮相关性使用，不让用户先填全表或提供正确诊断。优先交有理由的选择及本轮所需的实际文案、HTML或修复交接；说明直接影响它的事实、未知和下一步，不把索证清单当成果。

## 开始前

1. 确认日期、目标市场/语言、站点与业务模式、目标受众、Offer、主要业务结果、页面类型、证据时间窗、允许动作、批准人和停止线；缺失事实写 `UNKNOWN`。
2. 确认本次是教学、只读审计、计划、诊断还是草稿。用户只问原因时不要擅自改站。
3. 遇到当前 Google 功能、资格、政策、字段、界面、schema、Business Profile、AI 搜索或高漂移事实，先读 [当前 Google 事实门禁](references/current-google-facts.md)，并在使用当天复核官方原文。AI Search 任务要先检查 Search Console property 的 generative AI inclusion control、父属性继承和报告可见性，再讨论内容或 GEO 实验。
4. 涉及来源、第三方指标、素材权利、AI 内容、外链、账号或客户数据时，读 [证据与安全边界](references/evidence-and-safety.md)。
5. 追溯读[命题登记](references/source-register.json)。迁移/商品读[生命周期与结构化](references/lifecycle-and-structured-data.md)，Local/编辑读[Local与编辑判断](references/local-and-editorial-authority.md)。官方当前适用的已观察正文可以支持具名平台事实，首发unknown不再单独阻塞，也无需逐页日期例外；非官方来源仍遵守2024-08-01日期窗。观察日、更新日与事件日分别记录；未观察、正文冲突、实际资格、访问停止和执行授权不因新规解除。 四组2026-09-06选段可支持各自窄命题，不认证完整迁移、Product/Offer/GBP资格或法律合规；超出正文与实际输入的结论NEEDS_RESEARCH，仍交有内容的有限草稿。
6. 同时涉及付费搜索时，读 [SEO—Google Ads 交接](references/seo-ads-handoff.md)。共享输入，不合并归因，不把广告访问解释为自然排名因素。

没有 Search Console、Analytics、日志或 CMS 权限时，不自行登录。生成限定字段和时间窗的 `delegated_evidence_request`，让获授权负责人提供脱敏导出；拿不到就保持 `UNKNOWN`。

新手先读 [中文快速开始](QUICKSTART.zh-CN.md) 和 [使用说明](USER_GUIDE.zh-CN.md)。最短阅读顺序：先辨认 `canonical`、`rendered content`、`crawlable links` 与 `GSC status` 是已观察值还是未知，再找第一断点；AI Search 另使用 `generative_ai_search_gate`，结构化数据另使用逐类型资格卡。字段释义见工作流第 2、5、10 节。

## 公司主路径

`业务真值 → 权限与证据 → 发现/抓取/渲染/索引 → 架构与意图到页面 → 页面价值与内容 → 本地/结构化/多媒体 → 安全权威获取 → GSC/GA4/业务结果 → 优先级与单变量验证 → 停止/回滚/交接`

先确认页面为谁解决什么任务，再讨论关键词、字数、schema 或外链。先确认是否能发现、抓取、渲染和索引，再解释排名与流量。平台可见性不是业务价值；相关变化不是因果。

## 输出合同

普通运行只使用以下主状态：

- `DRAFT`：离线可检查的建议、brief、模板或计划。
- `NEEDS_FIX`：已有证据证明当前对象存在影响本次目标的缺陷。
- `NEEDS_RESEARCH`：有明确问题或假设，需要补特定证据。
- `UNKNOWN`：信息不足，不能判断原因或结果。
- `HUMAN_GATE_REQUIRED`：下一必要动作涉及真实账号、客户数据、Production、发布、删除、迁移、支付、预算、密钥、SQL 或其他需人工授权的外部变更。

报告级只选择一个状态，按 `HUMAN_GATE_REQUIRED > NEEDS_FIX > NEEDS_RESEARCH > UNKNOWN > DRAFT` 排序；只考虑完成本次明确目标所必需的阻断。不要在普通运行中使用 `PASS_*`、`REVISE`、`REJECT`、`READY_FOR_FINAL_QA` 或 `SHIP`，这些属于独立质检/项目状态。

按本轮目标就近说明以下必要信息，不在中间回合机械重贴无关旧审计；关键事实、未知和停止条件不能省略或只藏在附录：

`已知事实｜关键未知｜证据来源与日期｜首要断点｜建议动作｜保持不变｜验证字段｜观察窗口｜成功证据｜停止/回滚｜人工批准项｜结论边界`

用户补充一句时，先辨认是事实/证据改变、优先级调整还是明确换目标，定位页面、市场/语言、商品变体和素材版本。沿实际依赖重看 title/meta、标题/正文/FAQ、HTML、链接/图片备注或技术建议，仅修改受影响部分并撤回失效结论；一页或一变体的新事实不扩到所有页面。已成立且无关的判断、页面关系及未完成目标继续保留；新目标明确替代旧目标时相应调整，不机械守旧。涉及语言关系才回到 I1，不因文案改动无故改 canonical。

交出用户本轮要求的当前完整可用稿、关键改动与必要待办，不能只给“其他不变”让用户拼接，也不重贴全套审计。消费者正文与内部缺证备注分开，但影响使用适用性/安全的限制不隐藏。缺图只停依赖真实图的结论/资产，不拖停有文字依据的稿；本地稿、发布/技术状态、搜索与业务效果继续分层。

## 必须拒绝或停止

- 保证收录、排名、流量、AI 引用或收入；把固定字数、关键词密度、链接数量、发帖频率或第三方分数写成 Google 规则。
- PBN、GSA、过期域名网络、付费 dofollow、批量平台属性/评论链接、CTR/地图/评论操纵、虚假 Business Profile、假作者/体验/案例、制造榜单共识或规模化低价值页面。
- 把 `llms.txt`、schema、sitemap、广告访问、社媒互动、停留/跳出或一次 AI 回答当成自然排名因果或保证。
- 在没有来源、权利、事实核验、隐私、人工抽样、失败处理和回滚时自动生成、抓取或发布。
- 遇到登录、OAuth、API key、Search Console/GA4/GBP 真实账号、客户/查询数据、Production/CMS 写入、域名/DNS、迁移、删除页面、发布或付费动作时，标 `HUMAN_GATE_REQUIRED` 并停止该动作；可继续不依赖权限的离线分析。

不要用本地报告、通过结构校验、请求收录、提交 sitemap、部署完成或截图代替 Google 实际抓取/索引、客户验收、业务结果或人工批准。
