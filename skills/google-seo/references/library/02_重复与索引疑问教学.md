# 教学：什么时候考虑canonical，索引疑问先查什么

2026-10-19；沿用Drawerline原创合成情境，非真实抓取/账号/业务测试。本稿只说明怎样审材料和交具体提案，不执行代码、改配置或发取证请求。

## A｜相同主题不等于重复页

P1测量指南、P2分类、P3商品、P4护理承担不同任务。共同出现“drawer dividers”不能证明它们是重复内容，不能只因词频相近就把P1/P2的canonical都指向P3。文案修改也不是迁移URL的理由。

本段另给合成技术材料D1：

- P3为 `https://drawerline.example/products/divider-long`，声明self canonical。
- D1为同址加 `?utm_source=guide`；导出的完整正文、商品、价格、语言与P3一致，没有不同选项/功能。D1当前canonical指向带参数的自己。
- 业务负责人已确认首选公开商品地址为P3无参数地址；两个URL都应继续可访问，不请求重定向或删除。材料日2026-10-18，是真值卡与HTML导出，不是Agent现场抓取。

在这个明确同内容、同任务、同版本和首选地址的条件下，选择对齐D1的首选信号，而不是合并不同任务的P1/P2。具体本地拟稿：

```html
<!-- D1中本次唯一拟替换的canonical行，不是完整head替换 -->
<link rel="canonical" href="https://drawerline.example/products/divider-long">
```

P3自己的canonical保持原值；内部推荐链接使用给定无参数P3。其他参数URL未提供，不能批量套规则：参数若改变商品/语言/有独立用途，须重新核页面等价性与任务，不能先删除参数。

这只是减少本案同内容首选信号分散的提案，不证明现有配置造成了没流量，也不保证Google采用。保留源HTML/旧值、对象和版本；实际应用前由技术负责人核响应、HTML/其他声明与必要站点信号是否一致，未知项仍未知。不得顺手改robots/noindex、做全站重定向或删除D1。[Google canonical说明](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls)

## B｜“最近七天零点击”不是索引诊断

新增题面只有一句：P3最近七天没有自然点击。没有给property、筛选、日期范围、索引状态或Google已处理版本。报告主状态 `NEEDS_RESEARCH`：点击情况甚至口径尚未闭合，不能判断未收录、被惩罚、JavaScript失败或canonical失效。

现在最先要的是**指定URL的已有indexed检查记录及其时点**，而不是改标题十遍、去掉所有canonical、全站扫描或请求大量收录。本地已有测量指南/商品稿可以继续审，不被索引未知全部阻断。

可直接交给获授权负责人的取证草稿（未发送）：

> 请提供P3完整URL在对应Search Console property中的已有URL Inspection indexed记录，附生成日期/时区、页面索引状态及原因、最近抓取时间、抓取/索引允许信息、页面获取结果、用户声明及Google选择的canonical（若该记录可提供）。同时说明这份记录对应哪个页面版本；如只拿到live结果，请明确标live，不代替indexed状态。请先用已有脱敏导出或文字摘要，不提供账号、token、客户信息或完整查询/日志。若无法获准提供，保留未知，不为本草稿登录或改站。

“七天零点击”的性能记录之后还需核精确页面/日期/市场/设备/搜索类型及筛选；当前不把它补写成完整总量，不根据它推断索引原因。

### 收到证据后，怎样选下一步

|实际提供的证据|这时优先做什么|不能推出什么|
|---|---|---|
|indexed状态显示已索引，Google首选是预期P3|把问题转向同口径呈现/查询与页面任务；先核性能筛选、曝光与点击，不继续声称未收录|已索引不保证有排名、点击或订单|
|indexed记录显示被robots阻止|请技术负责人提供该URL、对应日期下相关robots规则与抓取对象的脱敏片段，定位实际阻断范围|不直接删除整个robots文件，也不把未读页面的noindex猜成原因|
|indexed记录显示重复，Google选了别的URL|取得那个实际被选URL的内容、用途及首选信号，与P3比较；先查是否预期同内容归并|不是一律给全部页面self canonical或用noindex强迫选择|
|只有live“可访问/可索引”结果|保留其测试时间与返回范围，仍需要indexed记录判断Google目前处理状态|live成功不证明已索引，也不预测Google选谁作canonical|
|仅给初始HTML为空壳|请技术负责人给同一页面/版本的初始与渲染后关键正文、链接、时间及证据来源；确认有缺项后，再查对应资源依赖|空壳本身不证明JS全失败或Google未渲染/未索引，不自动选择SSR|
|只给一个裸403|先请技术负责人明确被拒URL、顶层文档或子资源、请求来源与时间（普通浏览器、Google测试或日志）；顶层文档先定位该文档请求受拒的上下文，子资源再查发起关系及关键正文/链接依赖|未定位请求对象前不归因JS，不由403断言Googlebot被封，也不自动选择SSR或关闭防护|

URL Inspection区分已处理的indexed记录与实时测试；实时测试不覆盖全部索引条件，也不能保证被索引。[Google URL Inspection说明](https://support.google.com/webmasters/answer/9012289?hl=en)

### 带时间的追加情境

如果后来只给：10月8日indexed记录显示“Crawled - currently not indexed”，最近抓取10月7日；页面编辑改动于10月15日；10月18日live结果可访问。正确接续是：旧记录反映旧处理状态，live反映另一个时点的可访问性，两者不矛盾，也不能合成“10月18日已收录”或“改稿失败”。

先保存三段时间/版本与原始字段。若要判断新版本的Google处理，需后续获准indexed记录或相应Google侧证据；不设保证天数，不自动重复请求收录。若有具体渲染缺项，再沿相关资源取证，而不是拿未索引状态直接归因渲染。

## C｜国际化保持自己的方法和证据

语言/地区关系不是上述canonical问题的改名：先核各版本是否承担同一页面任务，拿到真实版本URL、内容对应、已有标记载体和日期，再使用[国际化I1方法](原版方法/payload/google-seo-operations/references/international-implementation.md)交逐页具体拟稿。不能只因一页德语就把不同商品归成翻译版本，也不为内容改稿顺手改变canonical。

现有I1已有英德HTML离线应用及旧限定独立审查；本轮不复制旧审查答案作为新教学成果，不重跑或伪称新验证。HTTP Link、sitemap、复杂语言/跨站及真实Google采用的证据差额仍保留。旧localized-versions的一次重读许可已经用完，本轮没有重试它或其他具名停止来源；使用当前复杂分支前，需要对应授权与决定性的现行证据。
