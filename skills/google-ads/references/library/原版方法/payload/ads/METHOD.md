## 选择任务模式

- `teach`：解释概念、判断方法、常见误区和安全操作顺序。
- `audit`：审查用户明确提供且获准使用的脱敏说明或导出，区分事实、假设和缺口。
- `plan`：把业务目标、利润、页面、商品数据、测量与损失上限转换为测试合同。
- `diagnose`：按测量、搜索词或商品资格、广告与页面、业务结果、竞价和样本顺序找第一处证据异常。
- `draft`：只生成拟创建的声明式对象及审批单；对象建议状态写成 `PAUSED`，不表示平台中已经创建。

多模式任务优先使用 `audit → diagnose → plan` 或 `audit → plan → draft`。PMax 使用完整离线 `pmax_plan_and_paused_draft`，实验使用独立 `google_ads_experiment_plan`；两者不能被普通渠道路由卡或前后对比替代。详细字段和五个 Google 方法单元见 [工作流与模板](references/workflow-and-templates.md)。

先用用户已经给出的目标、事实和材料判断本轮要作的广告决定，再加载对应方法。下列开始前清单按本轮相关性使用，不要求用户先选对模板或补齐全账户字段；只询问会改变本轮结论的关键缺口。先交有理由的选择、用户所需的实际稿件和优先动作；完整 PMax 方案或实验合同仍按任务交全，不以摘要代替。

## 开始前

1. 确认日期、市场、语言、币种、时区、业务主结果、利润或 CPA 上限、最大测试损失、页面、商品数据、授权人和证据范围；Shopping/PMax 任务还要把目标市场回接到 Merchant Center 的目标国家与对应 marketing method。
2. 澄清目标模式与本次输出；缺失事实写 `UNKNOWN`，不补猜。
3. 涉及当前功能、字段、界面、资格、迁移、政策或默认设置时，先读 [当前平台事实门禁](references/current-platform-gates.md)，并在使用当天查 Google 官方原文。PMax 字段逐项标 `required_for_this_plan`、`conditional`、`not_applicable` 或 `unknown_needs_evidence`；Google 推荐项不能自动成为经营决策。
4. 涉及讲师经验、跨平台数据、来源权利、真实账户或个人数据时，读 [证据与安全边界](references/evidence-and-safety.md)。
5. 追溯来源读取 [命题登记](references/source-register.json)，不依赖课程原件或其他Skill。渠道比较或Demand Gen任务另读 [专项研究边界](references/channel-choice-and-demand-gen.md)。首次用户从 [中文快速开始](QUICKSTART.zh-CN.md) 起步；未知与失败处理见 [使用说明](USER_GUIDE.zh-CN.md)。
6. 官方当前适用正文可支持具名平台事实；首发unknown不再单独阻断，不再逐页申请日期例外。非官方来源仍须证明2024-08-01及之后发布。未读、冲突、访问停止、历史/版本/地区/资格限制及修改授权保持独立，不把页面存在等同所有命题获证。

没有账户权限时，不自行登录补证据：使用 [工作流与模板](references/workflow-and-templates.md) 的 `delegated_evidence_request`，让获授权负责人提供限定时间窗与字段的脱敏导出。测量不可信与 Merchant 问题并存时，先冻结扩量并闭合业务主结果与测量；Merchant 作为独立修复队列登记。

## 核心顺序

`业务真值 → 权限与风险 → 转化合同 → 测量 QA → 渠道与意图 → 广告/商品/页面 → 上线门禁 → 诊断 → 单变量实验 → 边际扩量 → 报告与交接`

先验证有价值的转化、价值、币种、去重、延迟和业务对账，再讨论预算或竞价。Search 从搜索意图、搜索词和否定词证据开始；Shopping 与 Performance Max 从 Merchant Center 商品事实和资格开始。平台指标用于定位问题，不单独证明因果、利润或增量。

`PAUSED` 只表示离线草稿声明的期望初始状态；不表示真实 Campaign、Asset Group、Listing Group、素材、否词或实验已经创建或暂停。任何账户写入、流量分配、预算或实验应用都进入人工门禁。

## 输出合同

普通运行只使用以下状态：

- `DRAFT`
- `NEEDS_FIX`
- `NEEDS_RESEARCH`
- `UNKNOWN`
- `HUMAN_GATE_REQUIRED`

单个对象只能有一个主状态；不同对象可以并列。报告级只选择一个状态，并只考虑完成本次明确目标所必需的阻断，优先级为 `HUMAN_GATE_REQUIRED > NEEDS_FIX > NEEDS_RESEARCH > UNKNOWN > DRAFT`。远期或可选的真实动作不能把已经完成的纯离线草稿自动提升为 `HUMAN_GATE_REQUIRED`。各状态的进入、退出与允许动作见 [证据与安全边界](references/evidence-and-safety.md)。

不得在普通诊断中使用 `NOT_READY`、`REVISE`、`REJECT`、`PASS_*` 或 `SHIP`；这些属于独立质检或历史资产状态。

本轮方案或报告按目标保留必要的已知事实、关键未知、证据日期、首要问题、最小可逆动作、保持不变项、观察窗口、停止/回滚、人工批准项和下一次回读字段；不为中间回合重复无关旧审计。

默认先交主结论及主状态的中文含义、用户要求的实际稿件、最优先动作与必要停止点；本轮需要的详细证据在同一次交付中随后给出，并能按对象或输入定位，不等用户追问才提供。关键分母、会改变决策的未知和停止条件须紧邻相关结论或建议，不能只藏在后面的细节中。

分层只改变呈现，不减少上述输出义务，也不以摘要、空表或索证请求替代能够完成的稿件。保留本次任务必要的 PMax 完整草稿与实验合同字段；复杂任务不强压字数，用户要求完整审计时仍交完整证据。缺证只停止依赖该证据的判断或动作，不阻断可完成的离线产物。

收到短跟进，先辨认它是补事实、改约束/优先级，还是明确换目标，再回接 Campaign/广告组/商品变体、市场和版本。沿“承诺与意图 → 文案/页面/商品字段 → 否词、测量或预算判断”的实际依赖更新：撤回被新证据推翻的结论，修改受影响的具体交付，保留无关且仍有效的成果和待办；不强行沿用已被用户改变的目标，不把一个变体的新事实扩到全部商品。交出本轮要求的当前可用稿和关键改动，不能只说“其余照旧”让用户拼接，也不重复整套审计。缺证只暂停相关结论，证据补齐不自动授权真实操作。

## 必须停止

遇到登录、OAuth、开发者令牌、API key、真实账户或客户数据、转化/商品数据上传、预算或广告对象写入、发布、付款、Production、全局安装或删除时，将对应动作标为 `HUMAN_GATE_REQUIRED` 并停止。可以继续不依赖这些权限的本地分析，但不得把审批单、草稿、旧截图或公开页面写成真实执行证据。
