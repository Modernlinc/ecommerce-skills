# Pinterest 本地导出字段与计算前置合同

状态：研究候选，等待单项范围审查。订单：PINTEREST-EXPORT-CONTRACT-20260908-01。
编写日期：2026-09-08；用途：人工整理已获授权的导出或摘要，为后续有界计算明确输入和停止条件。

本合同的英文字段标签是公司本地整理标签，**不是 Pinterest 原生 CSV 列名、API schema、上传枚举或当前平台定义**。必须从实际输入建立列映射，不能因名字相似就认定含义一致。本单不附数据、不运行计算器、不产生业务结论；也不完成 G06、整批 C0 或全 Skill 验收。

## 1. 使用者先交什么，审阅者负责什么

资料提供者负责说明来源、读取授权、实际列的含义及报告范围；不需要提交密钥、账号凭据或身份资料。本次没有授权读取真实客户数据。合成资料必须明示，不能当作真实平台验证。

审阅者保留原值，逐列记录“原列名 → 本地标签 → 对象与单位 → 证据定位 → 映射状态”。映射证据可以是同一已给报告的说明、表头注释或带位置的导出说明；仅凭经验猜测不算证据。未提供版本/说明就记 unknown，停止依赖该语义的计算，不自行开网页补规则。

所有对象 ID 作为字符串保留，不能去掉前导零；不自动合并、改名或删除原行。每项原事实、用户假设、公司解释分栏。状态标签也是本地标记，不可填回平台字段。

## 2. 每批资料必须有的范围记录

下列字段分为资料级和记录级；记录继承资料级值时，要能回接到明确的资料 ID，不能无说明地继承默认值。

|本地标签|语义、类型与单位|必需条件及缺失处理|证据与责任|
|---|---|---|---|
|source_id、export_id、snapshot_id|字符串；来源、具体导出、该次快照的身份|任何数值解释必需；缺则无法稳定定位，拒算相关数值|提供者给身份；审阅者保留文件名/摘要 ID 和已有校验标识，不拿文件名当日期|
|source_kind、source_format、format_version|文本；平台导出/人工摘要/明确合成及 CSV 等格式、已知版本|格式版本未给记 unknown；若影响列义则停止相应映射|实际输入说明；不将本合同当版本证据|
|evidence_locator|文本；工作表、行/列、段落等准确位置|每个值与映射均必需；缺失值不得靠另一行推补|审阅者保证不用私有绝对路径也能定位已交材料|
|object_type、object_id、row_grain|字符串；Pin/账户等对象及一行代表什么|每个比值和聚合必需；层级或粒度未知拒算|导出范围说明；同名 ID 不能证明跨账户或跨类型同一对象|
|account_scope、market_scope|文本；账户范围标识、地区及适用范围|比较/合并必需；无法确认就分开描述|只需范围标识，不索取账户凭据；不同范围不能默认为可合并|
|period_start、period_end、boundary_rule、timezone|明确日期或时间；区间起止、端点包含/不包含与时区|比值及合并必需；只有“本月”或时区未知不得默认补齐|提供者的原报告设置；日期级资料要注明日粒度及边界，审阅者不擅转 UTC|
|exported_at、data_as_of、data_state|带时区时间/状态文本；导出时点、数据截至点、实时估计或固定快照|需判断同快照；未知则不能认定同步；实时资料保留可能修订标记|不把导出时间当观察起止，也不把快照当最终不可变事实|
|filters、content_source、content_format、saved_scope|明示条件集合；过滤器、来源/格式、是否及如何包含保存传播|每个比值、比较与合并必需；“无过滤”也要明确；未给不默认一致|输入中的原条件；paid/organic/paid-and-earned等只保留原标签和说明，不猜现行含义|
|mapping_status、value_status|本地状态文本|已证映射、unknown、缺失、不适用、冲突分别记录；不能合并成0|审阅者标记，不改变原字段；不适用需理由|

同口径判断需逐项有依据：对象和粒度、观察区间及端点、时区、过滤器、来源/格式、保存范围、快照和单位。看起来数值合理不是一致性证据；不能只比较起止日期就批准计算。

## 3. 仅保留三个计数及其条件比值

|本地标签|拟整理语义、类型与单位|必需条件|缺失/异常处理|
|---|---|---|---|
|save_count|输入已证的保存计数；非负计数，单位“次”|要计算保存比值时必需；须有实际列映射和范围证据|空白、破折号、抑制值、无法解析值为缺失/未知；不填0|
|outbound_click_count|输入已证的站外点击计数；非负计数，单位“次”|要计算站外点击比值时必需；不能拿 Pin 点击列替代|同上；不能按相似列名补映射|
|impression_count|输入已证的展示计数；非负计数，单位“次”|两个比值的对应分母，且必须同口径|明确记录的0与缺失不同；零分母返回 N/A，不生成0%|

计数若为负数、混入百分号或货币，停止该行相关比值。千分位、小数点、缩写和舍入方式需要原格式依据，不能静默清洗或取整。平台估计值若不是整数，保留原值和估计标记；未有可解释的精度/单位合同前不纳入本合同的计数比值。

只允许以下数学关系作为未来实现的范围，当前未执行：

- 本地保存比值 = 同口径 save_count ÷ impression_count。
- 本地站外点击比值 = 同口径 outbound_click_count ÷ impression_count。

结果须同时给出原分子、原分母、单位、范围、映射证据和状态。默认呈现未乘100的比值；显示为百分比时必须显式标记换算与显示精度，保留未舍入底数。二者不是本合同对平台界面指标的重新定义，也不是人数比例。

某个计数明确为0且分母为正、其余条件齐全时，该比值可以是0；缺失分子不能产生0。异常大于1的比值不得裁成100%或擅自改值，应标记异常并先确认计数范围/定义，不解释为用户转化概率。

Pin clicks若输入已给，可只保留原数与标签；**Pin click rate未知，停用，不计算、不排名**。点击和保存不能相加成人数或相乘成漏斗，不能直接推出利润、因果效果或扩量建议。

## 4. 聚合、缺失、重复和重叠

聚合前先确定希望代表的对象集合和期间集合，并说明各行为什么可加：

1. 每行需有相同且已证的计数语义、单位和所需范围条件。
2. 对象分区须可证明互斥、没有账户汇总行与其 Pin 明细重复计入；期间拼接须可证明边界无重叠且覆盖目标区间。混杂窗口或无法证明可加时，只能分组保留，不能算一个合率。
3. 同一指标行的分子和分母必须成对纳入。聚合比值只可“分子之和 ÷ 对应分母之和”，不得平均行百分比，不用别的行补缺失分母。
4. 若有缺失/冲突行，不能静默丢弃后称全量。允许的部分小计必须列纳入行、排除行及原因、已知原始行数与覆盖边界；原分母未知就明确无法估计覆盖比例。小计只代表该子集。
5. 不同快照可能是同一观察范围的修订版本，不能相加。若需要选择版本，须有来源的版本关系和明确选取依据，并保留其他版本及选择说明。
6. 相同 ID、相同数值或同一订单的跨渠道记录仅是重复候选。标记相关来源/行和冲突点；无身份与范围证据，不自动删除行、合并事件或宣称平台已去重。

窗口不一致的行不能直接相除或混成合率。若未来确实要按互不重叠期间累计，必须先取得明确的目标总区间、各段端点和可加依据；本单没有提供这种数据或执行授权。

## 5. Pin 时间与解释边界

分别保留 pin_created_at（Pin 创建时点）、link_added_at（链接添加时点）和本合同的观察区间。三者不是同一日期，不能相互填补。

计算“年龄”还需明确比较端点 age_reference_at、时区、时间粒度和差值单位。创建时点、时区或比较端点任一未知，年龄就是 unknown；只有日期的输入不虚构小时级精度。未来若计算年龄，应明确是截至观察期末还是其他指定时点，不能使用“今天”作为隐含默认。

链接后来添加可能影响可解释的点击观察范围，但本合同不发明校正系数或回补点击。不同年龄、不同观察长度或不同来源的表现不能直接归因内容质量。无样本和独立因果证据不作效果判断，不设置通用发布时间、内容寿命或季节提前常量。

## 6. 事件、订单和金额只保留解释条件

这部分是后续诊断的证据要求，不是算法。至少分别记录：

|资料层|必要解释条件|缺失时的边界|
|---|---|---|
|原业务事件|业务状态、发生时点/时区、订单引用、原标签、采集渠道、原关联 ID、测试/真实标记、同意/授权状态|不能只看英文标签推断交易完成；具体交易与结算流程未明就保持未知，不补 ID|
|订单和金额|币种、金额单位、商品金额、税、运费、折扣归属、原真值定位|不沿用目录错币种或账户默认值；不能混币相加，也不能把收款合计直接当商品金额|
|退款与成本|退款对象及期间、覆盖商品/税运等范围、是否完整；已知成本项目和缺失项|退款不当负购买事件，不把unknown成本当0，不产生净利润结论|
|平台报表与窗口|报表自述范围、评估与优化用途、回溯长度、click/view类型及实际设置证据|不同窗口不能代换；不从Leads旧页推Sales默认值，不创建归因或ROAS算法|
|验证证据|业务交易→采集日志→逐事件接收/处理→测试诊断→平台去重→归因/经营，各层分别定位|本地日志、HTTP成功、相同ID均不能越级证明接收完整、去重成功或真实归因|

P14–P17只是既有有日期和范围限制的研究观察。当前合同不将其转成现行通用规则，不增加上传枚举、Tag 接入、事件合并、币种转换或退款归因方案；公司本地标签不能绕过这些平台事实的正式采用门禁。

## 7. 输出判断与唯一优先补证

每次整理后，先给当前状态，再给可继续的文字说明：

|分支|何时适用|允许输出|
|---|---|---|
|拒算|关键列映射、单位、分母、范围或同口径关系未知/冲突，或需要越权数据|逐项原值与冲突说明；不输出该比值或合率|
|N/A|分母有明确证据为0|N/A及零分母原因；保留原计数，不声称无效果|
|仅部分可算|有可独立证明同口径且无重叠的完整子集，其余缺失或冲突|限定子集的公式/待实现计算要求、排除清单和边界；不当全量结论|
|需要平台证据|结论依赖实际列义、接收/测试/去重、配置或窗口适用性|列具体缺少的证据层；不扩大成账号操作请求|
|可继续文字解释|计算不足但有可定位的原事实或材料缺口|说明已知/未知和对判断的影响，交可用整理结果，不用空表或全HOLD代替工作|

本单没有业务输入，因此不预先判定某行通过。后续实际整理时只选一个最优先补证要求：选择最早阻断当前目标比值的缺口，写清“哪一列/哪几行或哪项报告设置、需要什么证据、用于哪个判断、拿不到时保留哪项限制”。映射未知时优先要求已给导出的相关列说明及范围定位；若映射已证而缺分母，优先要求对应分母及同范围依据，不重复索取已具备材料。

该补证要求只建议资料类型，不授权读账号、传数据、开网页或联系他人。拿不到时交付有边界的文字解释或部分结果，停止受影响计算，不扩大取证范围。
