# 目录：从真值定位到责任

先分普通内容、网站元数据商品Pin、catalog商品和购物广告。文字brief存在不能证明catalog资格。资格未知允许诊断资料，禁止提交放行。

逐变体建立原值→同市场同版本商品真值→页面证据→差异→建议→owner→应读回证据。检查商品ID/同款家族、标题描述、数量用途、价格币种、目标页面、图片/权利与可售状态。家族标识不代替变体标识；币种错误不擅自换汇。相符项只叫“给定文字一致”，不能扩成实际解析合格。

## 摄入与分发分开诊断

先记录catalog/data source、商品ID、诊断时间、原始code/message/type、摄入状态、自然分发状态、付费分发状态和材料定位。没有某层材料就分别unknown；成功上传不等自然或广告合格，目录获批也不等每件商品获批。官方Diagnostics分开呈现摄入问题与分发问题，报告据此分栏，不合成一个“通过”。

将问题拆为给定证据确认的来源/文件范围或逐商品范围；仅凭代码、英文关键词或Warning标签不决定全量/单件影响或可分发性。例如官方列表中125行标为warning，但相应文字仍指出商品不能发布；实际判断须对照完整消息、对象、时间和分发回执。标签与文字不一致时原样保留并请求该对象证据，不擅改原表、不猜根因、不套其他平台错误码。

报告给“原始问题→受影响对象及范围→商品/页面真值→建议修订→责任人→需读回的摄入/自然/付费结果”。修订前后分栏，本地改字不等平台修好。资格或回执缺失时，给可执行的资料修订建议并保持对应放行HOLD；可独立完成的内容brief继续。不请求密码、上传feed、删除条目或改库存。

根因缺日志就保留unknown。较旧资料与较新真值只说明需要比对，不能证明所有字段失效或平台违反时限。保留原值，修改建议与实际修改严格分开。图片缺失不造URL，可售缺失不猜状态。

更新责任分为商品真值owner、资料转换owner、获授权的平台操作人、复核人。手动拟议方式下本地改字不等平台取得；托管方式仍需来源/采集/错误证据。没有回执时，上传、接收、逐项诊断和批准各自unknown。整来源无法取回与单商品字段错误不同；不得编造实际已发生哪种故障。

输出完整逐商品诊断和刷新职责，绝不产可上传表或转换请求。依据历史P04–P08与公司方法C019见[事实表](方法原包__payload__pinterest-operations__references__facts-and-evidence.md)；ND3的O02/O03当前具名事实见[本轮证据](方法原包__payload__pinterest-operations__references__round-two-evidence.md)。
